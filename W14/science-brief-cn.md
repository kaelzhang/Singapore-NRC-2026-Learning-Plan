# W14 科学简版 - 使用 Scratch 和 SPIKE 的计算思维

## 核心思想
机器人只有在程序清楚时，才能清楚行动。**计算思维** 指把问题拆成部分、寻找模式、选择重要细节、写出一步步规则，并调试。

食品系统想法只有被翻译成机器人能执行的动作时，才会变成机器人任务。

## 过去、现在与未来
过去，机器遵循固定机械模式、凸轮、齿轮和简单控制。后来，计算机让机器可以编程。Scratch 风格积木帮助初学者学习逻辑，而不必一开始就输入困难代码语法。

现在，Scratch 和 LEGO SPIKE 风格积木编程让学生可以编写电机、传感器、灯、声音、循环、条件、变量和事件。真实机器人中也有同样逻辑思想。

未来，机器人可能使用更多 AI，但仍然需要清楚目标、状态、数据、约束、安全检查和调试。好的思考仍然重要。

## 分解
**分解** 指把大任务拆成小步骤。不要从“解决 Mission Meals”开始。可以从离开基地、沿路线走、检测标记、停止、放下工具、推箱子、后退、转弯、释放和返回等步骤开始。

小步骤更容易搭建、编程、测试和解释。

## 模式与抽象
**模式** 是重复结构。许多任务有类似模式，例如：

```text
行驶 -> 对齐 -> 动作 -> 后退
```

或者：

```text
感知 -> 选择 -> 移动 -> 释放
```

**抽象** 指关注重要思想，暂时隐藏细节。真实食物浪费系统很复杂，但机器人模型可以使用四种标记：新鲜食物、快过期食物、不安全食物和可堆肥残渣。只要模型保留了重要决策，这就是可以接受的。

## 算法与顺序
**算法** 是清楚的一步步方法。食谱、路线计划、分类规则或机器人程序都可以是算法。

**顺序** 指指令的先后。机器人非常严格地按顺序执行。如果机器人到达物体前就打开夹爪，任务会失败。如果它后退前就转弯，可能撞到模型。

像读故事一样读程序：首先、接着、然后、最后。

## 事件、循环和条件
**事件** 会启动一个动作。在 Scratch 中，点击绿旗是事件。在机器人中，按开始、检测到颜色、触碰传感器或到达某个时间，都可以是事件。

**循环** 会重复指令。它适合巡线、检查传感器、移动多个物体或重复配送。循环需要退出规则，例如“重复直到到达目的地”或“重复直到计数等于 3”。

**条件** 是 if-then 规则。例如：

```text
如果标记是黄色，送到救助区
如果标记是红色，送到检查区
如果距离小于 5 厘米，停止
```

条件让机器人做选择，但它依赖可靠传感器和经过测试的阈值。

## 变量和状态
**变量** 储存信息，例如箱子数量、任务时间、传感器读数或当前路线。

**状态** 是系统当前阶段：搜索、识别、搬运、配送、释放、返回或停止。**状态机** 组织任务，防止机器人同时尝试做所有事。

如果机器人失败，问是哪一个状态失败。这会让调试更容易。

## 传感器需要意义
传感器不像人一样理解世界。颜色传感器测量反射光。程序给这个读数意义。

这就是阈值和 **校准** 重要的原因。如果黄色有时读成绿色，队伍可能需要更好的光照、更近的传感器、更大的标记，或多检查一次的规则。

食品系统也是如此。温度传感器可以警告冷库太热，但人们仍然需要规则来决定接下来做什么。

## 调试
**调试** 指发现并修正错误。错误可能在代码、机构、传感器位置、电池、起始位置或策略里。

使用冷静的循环：

```text
观察 -> 命名问题 -> 猜测原因 -> 改一件事 -> 测试 -> 记录
```

一次改很多东西，会让学习变困难。

## 食品系统逻辑变成机器人逻辑
食品系统规则可以变成代码规则。

冷链：

```text
如果物品是冷食，送到冷藏区
否则送到干货储存区
```

浪费分类：

```text
如果食物是安全剩余食物，救助
否则如果可堆肥，堆肥
否则检查或处置
```

气候韧性：

```text
如果路线被堵，使用备用路线
如果看到高温标记，送遮阴资源
```

编程就是把意义翻译成行动。

## 与 Mission Meals 的连接
强大的机器人程序有清楚任务、小步骤、可重复模式、经过测试的传感器规则、命名变量、状态和调试记录。

伪代码在积木编程前很有帮助。它让搭建者、程序员和讲解者在写代码前先同意计划。

## 需要记住的更多细节
伪代码在积木前很有帮助。它是普通语言写的程序逻辑，不是最终代码。队伍可以写：去货架、扫描标记、如果黄色就送到救助区，否则留在原处，回到检查点。搭建者、程序员和讲解者都能理解。

数据流是信息在程序中的路径：

```text
传感器读数 -> 变量 -> 条件 -> 动作 -> 新的传感器读数
```

如果其中一环弱，机器人可能表现奇怪。调试常常就是找出弱环节。

程序应该处理的不只是完美路径。完美路径是所有事情都刚好正确时发生的情况。真实任务可能需要备用状态：重试、倒退、停止、重新对齐或请求重置。

编程笔记应该记录版本、改变了什么、为什么改变、测试结果和下一个想法。这说明队伍是用证据改进，而不是随机猜测。

## 关键要点
计算思维帮助你把大的食品问题变成机器人逻辑。机器人需要精确指令，但队伍需要理解更大的意义。好的程序可读、可测试，并连接到科学故事。

最后检查：选择一个任务。写出一个顺序、一个条件、一个变量和三个可能状态。
